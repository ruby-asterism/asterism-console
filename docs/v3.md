# V3: plots and a log list

Stage V3 of the console (plan: "V の続き", the roles of rqt_plot and
rqt_console). Done 2026-10-09 on asterism 0.4.0, and checked the same day
against a real network: zenohd and ROS 2 Jazzy (rmw_zenoh) in docker,
rclcpp's talker and listener, an rclpy node publishing a varying
`/cmd_vel` and `/imu`, and a CRuby process putting MessagePack on Asterism
keys.

## What it adds

- **Plots** (`/plots`, "Plots" in the navigation): pick a ROS 2 topic (or
  type an Asterism key), tick its numeric fields or type a path, add them to
  a plot. A plot holds up to 8 series (fields of one topic or several), the
  page any number of plots. Each plot has a window (the last 10, 30 or 60 s),
  pause / resume (a paused plot stops redrawing; its series go on filling,
  and the chart's own zoom and cursor work), a remove button per series and
  per plot, and a table with the latest value of each series.
- **Logs** (`/logs`, "Logs"): `/rosout` of every ROS 2 domain and the
  Asterism log keys (below), newest first: time, level, node (the logger
  name), message, file:line, function. Filters: level (at least), node (a
  part of the logger name, with the names seen offered), text (in the
  message, file and function). Pause (lines that come meanwhile are kept and
  shown on resume), clear, and a bound of 2000 lines. Levels are coloured
  (DEBUG grey, INFO blue, WARN amber, ERROR and FATAL red) and always named.
- **From the graph**: a ROS 2 topic's details and each topic of a topic
  edge have "Plot this topic" (the plot page in a new tab, the topic picked);
  a ROS 2 node's details have "Show its logs" (the log page, its node filter
  set to the node's logger name: `/talker` -> `talker`, `/ns/talker` ->
  `ns.talker`).

## How decoding and field selection work

- **The type of a ROS 2 topic** is the one in its liveliness tokens (the
  graph's topic node), never one the page sends. The bridge loads it with
  `Asterism::ROS.require_type`: asterism's bundled types (its `data/msgs`)
  and the console's own `vendor/msgs` (`rcl_interfaces/msg/Log`, generated
  with asterism's `tools/asterism_msggen.rb` from the Jazzy definition; the
  type hash matches the one rmw_zenoh puts in the data keys). Only names of
  the form `pkg/msg/Name` (lower-case package, capitalised name) are looked
  up (`Bridge::Types`): the name comes from the network and becomes a file
  path.
- **The field list** comes from the type definition: a message with every
  field at its default (`type.new.to_h`), walked for numbers
  (`Bridge::Fields.paths`): nested messages as `linear.x`, fixed arrays by
  index (`orientation_covariance[4]`, at most 16 indices per array),
  booleans as 0 / 1. Sequences are empty in a default message, so they are
  offered as `position[0]` ("edit the index"). Once messages arrive, the
  bridge also looks at the fields of the latest one every 2 s and adds what
  it has (a sequence's real elements, the keys of an Asterism Hash).
- **A path** is names and indices: `linear.x`, `position[2]`,
  `poses[0].pose.position.x`, `""` for a payload that is a number itself
  (`Bridge::Fields.parse`; checked by the lease model and again by the
  bridge). A path that is not in a message, or is not a number, gives a gap.
- **Unknown types**: a topic whose type has no generated file is not
  subscribed; the picker says "type rcl_interfaces/msg/ParameterEvent is not
  bundled (...)". A topic not on the network says so too. Both are tried
  again on the next sync (0.5 s), so a topic that appears later just works.
- **Asterism keys** (the stretch goal, done): `key:<key expression>`. The
  payload is read as MessagePack (a Hash: paths into it, `accel[2]`,
  `temp`; a number: path `""`), else as text that is a number. MessagePack
  comes first, so a one-character text payload `"5"` reads as the
  MessagePack integer 53. Key expressions starting with `@` (the admin
  space) are refused.
- **/rosout** is decoded with the generated `rcl_interfaces/msg/Log`
  (`Bridge::Logs.ros_line`): time from the message's stamp (the receive
  time when it is 0), level, logger name, message, file, function, line.

## Leases: subscribed only while a page is open

`StreamLease` rows, like V2's `RateLease`: kind (`plot` / `log`), a random
token per open page, the target (a topic id, `key:<expr>`, or `*` for the
logs), the fields, 30 s. The page sends everything it wants every 10 s and
at once when it changes (`POST /plots/lease`, `POST /logs/lease`; a renewal
replaces that page's rows only), and on `pagehide` / leaving the page it
releases them (`navigator.sendBeacon` to `POST .../release`). A page that
just disappears (a crash, a closed laptop) is forgotten when its rows run
out. The bridge reads the live rows every 0.5 s:

- plots: one subscription per target, however many pages plot it
  (`<domain>/<name>/**` for a topic, the key expression for a key), with the
  union of the fields all pages want; it writes what it knows of the target
  (type, fields, error, fields seen) into the rows' `meta` (the lease answer
  carries it) and broadcasts it as `plot_meta`.
- logs: `<domain>/rosout/**` for every ROS 2 domain seen, and
  `asterism/*/*/log`, while any log page is open.

Logged by the bridge: `plots: subscribe 0/cmd_vel/** (r_topic:0/cmd_vel)`,
`plots: r_topic:0/imu: 2 fields (...)`, `plots: stop 0/imu/**`, `logs:
subscribe 0/rosout/**`, `logs: stop asterism/*/*/log`.

The points and lines go on streams of their own (`ConsoleChannel` with
`stream: "plots"` / `"logs"`), so the graph page does not receive them.

## Costs and bounds

| | Bound |
|---|---|
| Plotted targets (bridge) | 16; fields per target 32 (all pages together); per page 8 targets, 16 fields per target |
| Decimation | at most 30 messages per target and second are kept (the first of each 1/30 s slot); every field of a target gets at most 30 points a second |
| Waiting for the main thread | 64 raw messages per target; a message over 256 KB is not decoded (counted as an error) |
| Broadcast | every 0.2 s, one `plot` message with the points of all targets and one `logs` message |
| Log lines | 1000 raw messages between drains, 200 decoded lines a second; the rest dropped and counted (shown on the page) |
| Page memory | per series the last 60 s, at most 2000 points; the log list 2000 lines (and 2000 held while paused) |

Measured on this PC (Ruby 3.2, `bin/rails runner`): `Plots#record` 0.33 us
per message (it only decimates), decoding an Imu 16.7 us and a Twist 3.3 us
(the generated pure-Ruby types), taking one field out 0.37 us, a /rosout
line 6.3 us. So a 1 kHz Imu costs the bridge about 0.3 ms of counting and
0.5 ms of decoding per second. As with the rates (V2), the real cost is the
traffic: every message of a plotted topic reaches the bridge (over a relay,
across it), decimation only saves the decoding and the browser's share.

## The Asterism log key (a proposal)

The console shows log lines that Asterism nodes put on

```
asterism/<node>/<app>/log      MessagePack Hash
  "level"     "debug" | "info" | "warn" | "error" | "fatal" (or 10..50, as ROS 2)
  "msg"       the text
  "time"      seconds since the epoch (Float); the receive time when missing
  optional:   "name" (default "<node>/<app>"), "file", "line", "function"
```

for example `{"level" => "warn", "msg" => "low battery", "time" => 1791531280.1}`.
It is a `put`, not a liveliness token or a query, so it does not show in the
graph and does not clash with an object named `log` (an object's keys are
`.../<object>/call` and `.../meta`). Nothing in the gems or on the boards
sends it yet; this is the console's side of the proposal only. A payload
that is not a Hash is shown as an INFO line with its text.
