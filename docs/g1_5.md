# G1.5: roles, calls under one's own name, opening the browser build

What the registry's ACL is made from since G1.5, and the button that opens
a browser build for the signed-in user. Earlier design: `docs/g0_w4.md`.

## Roles

A role is a name and key templates (Admin > Members > Roles). A row of the
registry picks any number of roles; the cloud router's ACL gives the row
what its roles allow. `${node}` in a template stands for each node the row
speaks for: the list "Nodes it speaks for" (the nodes behind a home
router), or the row's own name (a node that connects directly, whose
certificate name is its node ID).

A role has four lists, one per kind of access:

| Section | zenohd rule | Meant for |
|---|---|---|
| Read and write | every message, both directions | the role's own place: `asterism/${node}/<app>/**`, `asterism/${node}/@profile` |
| Read | from it: declare_subscriber, liveliness_query; to it: every message | what it may see: `asterism/*/<app>/**` |
| Ask | from it: query | Asterism calls and meta are queries: `asterism/*/<app>/*/call/${node}`, `asterism/*/<app>/*/meta`, `asterism/*/@profile` |
| Watch | from it: declare_liveliness_subscriber | the asterism gem's one watch, `asterism/**` |

- A template with `${node}` becomes a rule of the row's own, expanded to
  each of its nodes; a template without it is the same for every row and
  becomes one shared rule (`role__<role>_<section>`).
- The templates carry the app name. There is no app that is "the game" for
  the whole console any more (`ASTERISM_RELAY_GAME` is gone).
- A row's own key lists ("Other keys it may read and write / only read")
  stay, for what is not a role (the console's own `asterism/**`). A new row
  starts with none (G0 put `asterism/**` there by default, which let a home
  router through with everything).
- The pages show what a role becomes: the role's page lists every row that
  has it with the keys expanded, and a row's page lists what its roles
  allow.

### Calls under one's own name

An Asterism call is a query on `asterism/<node>/<app>/<object>/call/<caller>`
(asterism `docs/protocol.md` 4.7). Allowing queries only on
`asterism/*/<app>/*/call/${node}` means a row can call only under the
names of its own nodes: a call that names someone else gets no answer
(the caller sees "nobody answers"). Meta and profiles are asked as before.
Checked against zenohd 1.10.1 (fmruby-core
`doc/ruby_asterism/report/g1_5.md`).

What the router cannot tell apart: the nodes behind one home router share
its certificate, so one of them can write and call under another's name
from the same list. The browsers share one subject (below).

### The seeded role "match"

A new console starts with one role, "match" (`db/seeds.rb`), an example
for playing a game of the app `game` against others:

```
read and write  asterism/${node}  asterism/${node}/game/**  asterism/${node}/@profile
read            asterism/*  asterism/*/game/**  asterism/*/@profile
ask             asterism/*/@profile  asterism/*/game/*/meta  asterism/*/game/*/call/${node}
watch           asterism/**
browsers        yes
```

Change it, remove it, or add roles for other apps. A console migrated from
G0 gets the same role from the migration
(`db/migrate/20261013100000_relay_roles.rb`, for the app in
`ASTERISM_RELAY_GAME` when it is set), and every row that was "Player" has
it, with its node list unchanged. The ACL made after the migration means
what G0's meant, with calls narrowed to the caller's own names
(`test/lib/relay/role_migration_test.rb` asks both ACLs the same questions).

### Looking only: a viewer role (0.3.4)

An admin who wants to see the whole network from a terminal or an AI
assistant, without being able to change anything, gets a row with a role
that reads everything and calls nothing. The asterism gem's command line
takes the row's `.tar`: `asterism tree --credentials viewer.tar`,
`asterism watch --credentials viewer.tar`, `asterism mcp --credentials
viewer.tar` (asterism README, "The command line"). Admin > Members > Roles,
"New role", `viewer`:

```
read and write  asterism/${node}/**  asterism/${node}/@profile
read            asterism/**  asterism/*/@profile  asterism/*/*/@status
ask             asterism/*/@profile  asterism/*/*/*/meta  asterism/*/*/@status
watch           asterism/**
browsers        no
```

Then Register, kind `client`, a name for the person (`admin-viewer`; the
certificate's name is the node ID the command line connects as), role
`viewer`, "Issue a certificate", "Save all (.tar)", and Apply.

- **Read** `asterism/**` lets the router send it every node's tokens and
  puts (the tables' states, the graph's own view), and the answers to its
  meta queries. A `**` does not match a chunk that starts with `@`, so the
  profiles and the applications' statuses (asterism `docs/protocol.md` 7
  and 8) are listed on their own, in Read and in Ask.
- **Ask** has the meta of every object (`asterism/*/*/*/meta`; the
  command line asks `asterism/<node>/<app>/*/meta` for each app, and each
  node's profile and each app's status by its own key: a query with a
  wildcard over the nodes would have to fit every node's rules at the
  router) and no `.../call/...`: the router
  refuses every call the row makes. `asterism call` then says "nobody
  answers", the same as for an object that is not there; nothing runs.
- **Read and write** is its own place only, so that the command line's
  application shows up in the graph (`asterism/<its name>/cli-xxxx`) and
  can say what it is (its profile). Leave the line out and it connects all
  the same, unseen (the router drops its tokens).
- The game host's spectate keys (`asterism/<host>/spectate/<table>/state`,
  the tables with the four mahjong hands, docs/rooms.md "Watching the
  tables from outside") are under `asterism/**`: the viewer reads them,
  with the MCP bridge's `asterism_values` too. Give the role to admins
  only.
- The rooms stay closed (`room/**` is not in the role): a room's tables are
  seen in the console's graph only. With the role's keys checked against
  the router's rules by `test/lib/relay/viewer_role_test.rb`.

## Browsers

zenohd sees every browser that comes through `ws/` as one session subject
(no certificate, and zenoh-pico has no user name); since T8 a user's own
page comes through `tls/` with a certificate of the user's instead (below,
"Browsers the router tells apart"). That subject gets the roles marked "Browsers
have this role", with `${node}` = `<prefix>$*` (`ASTERISM_BROWSER_NODE_PREFIX`,
`wasm-`). So one browser can still write and call under another browser's
node ID; it cannot under a registry row's.

### Open the browser build

With `ASTERISM_BROWSER_PAGE` set, the Browser passes page has "Open the
browser build" ("Launch Web Studio" from 0.3.5, on Make a pass and in the
menu). It makes a pass, picks a node ID for the user and opens the
page in a new tab, starting an app the user chooses: nothing, or one of a
list an admin keeps (Admin > Studio apps, from 0.3.12; before, each role
named one, "Opens in a browser page", and the 0.3.12 migration copied
them to the list). The console opens no app that is not on the list.
Which keys a browser may use is still up to the roles marked "Browsers
have this role"; a role no longer says what a page opens. Without the
setting the button is not there, and passes work as before.

`ASTERISM_BROWSER_PAGE` is the page's URL with placeholders, each filled in
URL-encoded: `{router}` (`ASTERISM_PASS_ROUTER`), `{pass}`, `{node}`,
`{app}`. `{pass}` must be after the `#`: the fragment never reaches the
server that serves the page. For example:

```
https://play.example.org/?zenoh={router}#zenoh_pass={pass}&zenoh_node={node}&app={app}
```

The console hands the URL to the new tab in the body of a page that is not
kept (`Cache-Control: no-store`, no referrer), never in a redirect: Rails
logs a redirect's location. The pass is still used once.

The node ID (`Relay::BrowserNode`): `<prefix><name>`, the name made from
the part of the user's email address before the `@` (lower case, runs of
other characters than a-z and 0-9 made one `-`, at most 20 characters;
`user<id>` if nothing is left). Two users whose names come out the same:
the later one gets `.<user id>`. (Until T8c) a second page of the same user at the same
time got `_2` ... `_9` (the first that is neither on the graph nor named
by a pass still waiting or used in the last 30 s), then `_<3 hex>`. A name
never has `.` or `_` itself, so the suffixes cannot make another user's
name. The router does not check any of this.

(G1.5b replaced the name from the email address with the handle the user
chooses on the account page: `<prefix><handle>`; docs/g1_5b.md.)

### Every link names the node (0.1.2)

On a network the console runs, the console decides who a browser page is,
not the URL it was opened with. Every link the console gives a browser
carries the pass and the node ID from the user's handle: "Open the browser
build" (with the app), and the link a pass made with "Make a pass" is shown
with (the same template, `{app}` empty). `ASTERISM_BROWSER_PAGE` without
`{node}` is not used (no button, no links). A user without a handle is
asked to choose one before any pass is made; a pass shown without a link
(no page configured) is shown with its node, to be handed to the page
together.

The browser build (fmruby-core) refuses a link with a pass and no node: it
does not start and says to open it again from the console. Without a pass
(a network without a console: a home router, a development router) it
keeps the ID it makes itself (`wasm-<6 hex>`). The name a page shows (an
app's profile name) stays free; only the node ID is fixed.

### Browsers the router tells apart (T8)

The door (`bin/ws_door`) knows the user from the pass. Since T8 it
connects the user's own page to zenohd's `tls/` listener with a
certificate of the user's instead of `ws/`, so the router sees the page
as a subject by its certificate name, like a registry row or a room's seat.

- **Certificates** (`Relay::BrowserCerts`): one per user with a handle,
  named after the user's browser node, `wasm-<handle>`. The key is made on
  the server and signed by the signer (as the seats', `issue_unlisted`),
  365 days, renewed within 30 days of its end by `bin/asterism setup`; the
  browser never has it. They are made when the user chooses a handle, for
  every user with one by setup (an update runs it), and on Admin > Members
  > Browsers ("Make the missing certificates"). Store: the rooms' volume,
  `browsers/wasm-<handle>.pem` / `.key` (0600) and `ca.pem`, which the door
  reads already. A handle given up takes its files with it (and the door's
  list loses the name at once); a removed user too. A registry row with
  such a name is left out of the ACL: the name is the browser's.
- **Apply.** The ACL has the users whose certificates are good when it is
  made; a new one waits for the apply ("waiting to apply" on the Browsers
  page and on the user's account page; the apply banner shows as for any
  change). The apply (and setup) writes the door's list,
  `browsers/browsers.json`: the names the router's configuration lets in.
- **The door's word.** The pass check (`/passes/check`) answers, next to
  `X-Asterism-Until`, `X-Asterism-Browser: node=wasm-alice; pass=12;
  notice=1; until=...; mac=...`, signed (HMAC-SHA256) with a key the console
  keeps in the store (`browsers/door.key`); nginx hands it on to the door
  (`auth_request_set`, `proxy_set_header`; Caddy `copy_headers`). The door
  takes nothing from a word whose signature does not check, so a header a
  browser sent itself counts for nothing. `node` is the pass's node only
  when it is the user's own browser node: a link made before T8c with a
  second name (`wasm-alice_2`) or a pass for a handle given up names none.
  From T8c the word also says when the console first let the pass's page
  in (`opened=<Unix ms>`, `BrowserPass#used_at`).
- **Which way** (`Relay::BrowserDoor`): the page goes to `tls/` with the
  certificate when the word names a node, the node is in the door's list
  and its files are there, and no page opened later has the node; a
  page's own sessions and its reconnections come with its pass and take it
  again. Everything else goes to `ws/` as before: the shared subject.
- **The page opened last has the name (T8c).** The console gives every
  page the user opens `wasm-<handle>` (no `_2` any more). When a page
  opened later (by `opened`, then the pass) claims the name, the door
  takes it over: it closes the earlier page's connections with the
  certificate (a close frame, code 4409), and that page, which connects
  again by itself, goes through `ws/` with a notice that says so
  (`"taken_over": true`, why "a page opened later from the console took
  over wasm-alice"). The door remembers the latest page per name, not only
  while it is connected, so an earlier page does not take the name back
  while the later one is away; a door restarted forgets that, and the page
  opened later takes the name again when both connect. Both pages show the
  same node ID on the graph; only the later one is checked by the router
  and can send or receive files. On `tls/` the door ends the WebSocket itself and moves
  the batches as the rooms' door does: one WebSocket message is one batch,
  on TLS a 2-byte little-endian length and the batch, and the batch size
  of zenohd's InitAck is lowered by 2 (`Relay::WsFrames`, shared with the
  rooms' door; fmruby-core `doc/ruby_asterism/report/g1_5.md` 7). The
  door's log says `as wasm-alice with its certificate (pass 12)` or, on
  `ws/`, `(shared: <why>)`.
- **The notice.** A page that asks (`door=1` in the WebSocket URL's query,
  next to the pass; Family mruby's browser build from T8 on) gets one Text
  message before anything of Zenoh: `{"door": {"verified": true, "node":
  "wasm-alice"}}`, or `{"door": {"verified": false, "why": "..."}}` on `ws/`
  (after zenohd's answer to the upgrade), with `"taken_over": true` when a
  page opened later has the name (T8c). An older page is sent none: it
  would take the Text for a batch.
- **The ACL** (`Relay::CloudConfig`, `test/lib/relay/browser_certs_acl_test.rb`).
  Like a seat, two subjects for the one certificate: the common name alone,
  with the roles marked "Browsers have this role" (`${node}` its own name)
  and a deny on every call (`asterism/*/*/*/call/**`); the common name with
  `link_protocols: ["tls"]`, with the calls those roles' ask lines make,
  the caller put as its own name (`asterism/*/game/*/call/wasm-alice`), and
  its sends of files. So it writes where its roles say, under its own
  name for a `${node}` line, and calls under its own name only, whatever a
  role's line. Files: below and docs/files.md.
- **The shared subject** (`ws/`) keeps its roles, with `${node}` =
  `wasm-$*` as before, but is refused every transfer key
  (`asterism/*/transfer`, `asterism/*/transfer/**`: a deny in its policy):
  files only with a name the router checked.
- What it costs: the door holds every user's key, so the door (and the
  rooms' volume) is where the trust is, as for the seats. zenohd sees every
  browser's connection coming from the door's address.

Before T8 this section was a study (fmruby-core
`doc/ruby_asterism/report/g1_5.md` 7): the framing and the InitAck rewrite
were found then, and the rooms' door (0.3.0) built them first.

## Apply still restarts the router

zenohd 1.10.1 cannot change its ACL while it runs: a write to the admin
space's configuration is refused for every key outside `plugins/`
("updating config is only supported for keys starting with `plugins/`"),
and the ACL is built once, when the router starts. Apply writes the file
and restarts the router as before (`docs/g0_w4.md`); browsers then need a
fresh pass, home routers connect again by themselves.

## Settings

| Variable | Default | |
|---|---|---|
| `ASTERISM_BROWSER_PAGE` | unset | the browser build's URL template with `{pass}` (after the `#`) and `{node}`; unset (or without either): no "Open the browser build" and no links |
| `ASTERISM_BROWSER_NODE_PREFIX` | `wasm-` | the browsers' node IDs: the ACL's `${node}` for browsers and the names the console hands out |
| `ASTERISM_STUDIO_URL` | unset | the plain pass link's page, only when `ASTERISM_BROWSER_PAGE` is not set (`?zenoh=`, `#zenoh_pass=` added); neither set: the pass is shown without a link. Before G1.5 it defaulted to one project's page |
| `ASTERISM_RELAY_GAME` | - | removed; read once by the migration |
