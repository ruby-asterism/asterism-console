# X1: wire protocol 1 (asterism 0.7.0)

Stage X1 of Asterism. asterism 0.7.0 speaks wire protocol 1 only
(asterism's `docs/protocol.md`); the console moves to it together with the
boards, the browser build and the CRuby programs. A console of this
version does not talk to nodes of asterism 0.6.0 and earlier (protocol 0),
and an older console does not talk to 0.7.0 nodes.

## What changed for the console

- **Calls and meta** go through asterism's API as before
  (`Bridge::Objects`); the wire form is the gem's. The meta is now
  `{"methods" => [{"name" => name, "arity" => n}, ...]}`: the page reads
  the maps (and still takes the old pairs, so a page open across the
  update keeps working).
- **The kind of a remote error** (`RemoteError#remote_kind`: `raised`,
  `not_exposed`, `no_object`, `arguments`, `malformed`, `unsendable`,
  `nesting`, `protocol`) is kept with the request (`bridge_requests.error_kind`,
  a migration) and shown in the call box (`remote error: [raised]
  KeyError ...`) and the call log.
- **Who called**: the console's calls carry its node ID in the call key
  (`.../call/console`); the called method sees `Asterism.current_call.from
  == "console"`. The call log still says which user asked.
- **Profiles** have `protocol` (1); it is part of the summary the graph
  keeps (`data.profile.protocol`). The icon arrives as a MessagePack bin
  (a binary String); the store keeps it as before.
- **Application tokens**: each application declares
  `asterism/<node>/<app>`, and the node token `asterism/<node>` is gone.
  `Bridge::Graph` draws an app from its token, so an app that exposes
  nothing (a pilot, the console itself) is drawn inside its node; the node
  is there while any of its apps or objects is.
- **Recordings**: the Asterism channels (keys, the network structure) get
  the channel metadata `asterism_protocol` = `"1"`. A recording without it
  was made with protocol 0: the timeline lists its channels and says
  "recorded with Asterism protocol 0 (before asterism 0.7.0)", and does not
  decode its Asterism keys (`Bag::Channels.protocol0?`). A bin in an
  Asterism key's MessagePack is shown as hex.

## Not changed

- The relay's ACL (`Relay::CloudConfig`) still lists `asterism/<node>` among
  a player's own keys; with protocol 1 nothing is declared there, and
  `asterism/<node>/<game>/**` covers the application token. Restricting
  calls to the caller's own name (`asterism/*/*/*/call/<name>`) is G1.5.
- The Gemfile's rubygems line stays `~> 0.6.0` until 0.7.0 is published;
  the checkouts next to this repository are what the console runs with.

## Checked

`bin/rails test` (278 runs). Against the Linux simulation's
`asterism_demo` and a CRuby node with an icon of its own: the bridge read
both profiles (`protocol=1`), fetched the new icon (165 B, 8x8), drew
`a_app:console/console`, `a_app:linux/demo` and `a_app:x1node/demo`, and
its calls came back with their kinds (`raised` KeyError, `not_exposed`)
and the caller `console` seen by the called method.
