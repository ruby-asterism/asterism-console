# V2: a graph that stays readable on a busy network, and topic rates

Stage V2 of the console (plan: "V の続き", rqt_graph and rqt_topic). Done
2026-10-09 against a recorded network (fixture mode), then checked against
a real network the same day, on asterism 0.4.0 (end of this page: what it
found and what was fixed).

## What changed in the graph

`Bridge::Graph` (lib/bridge/graph.rb) still builds typed nodes and edges
from the admin space and the liveliness tokens; the shape is new:

| Before (V1) | Now (V2) |
|---|---|
| Asterism node -> app -> object, edges `has_app` / `exposes` | apps and objects carry `parent` (app: the node, object: the app); no edges. The page draws compound nodes: node box, app box, objects |
| ROS 2 services as nodes (`r_service`, edges `serves` / `calls`) | no nodes: each ROS 2 node lists `services` and `clients` (`name`, `type`, `domain`, `parameter`). `parameter` marks `describe_parameters`, `get_parameters`, `set_parameters`, `list_parameters`, `get_parameter_types`, `set_parameters_atomically`, `get_type_description` |
| topics as nodes (`publishes` / `subscribes`) | `topic_link` edges from publishing node to subscribing node, one per pair, with `topics` (ids) and a label (names). Topics stay as nodes, with `publishers`, `subscribers` and `matched`, and the `publishes` / `subscribes` edges stay, for the topics-as-nodes view |
| (none) | a ROS 2 node's `unmatched`: the topics it publishes with no subscriber on another node, or subscribes to with no publisher on another node (`topic`, `name`, `type`, `role`) |

Routers, sessions, `carries`, `router_link` and the relay registry overlay
(W2) are as they were. A compound Asterism node shows its registry mark as
its border colour (a halo would cover the boxes inside).

## The page

- Toggles: "Topics as nodes" (V1's drawing of topics), "Hide /rosout,
  /parameter_events" (on by default, like rqt_graph's "Hide debug"; it also
  leaves them out of the badges and the edge labels), "Hz on topics",
  "Measure all topics".
- ROS 2 node: a badge in its corner (red: services, orange: topics with no
  counterpart). Details: publishes / subscribes (each topic with its rate
  and the nodes at the other end), topics with no counterpart, services
  with the parameter services folded (`<details>`), calls.
- Topic edge (click it): each topic with type, rate, bandwidth, messages,
  the last message (how long ago, size, preview) and "Watch its values".
- Layout: fcose (cytoscape-fcose 2.2.0, cose-base, layout-base, vendored by
  `bin/importmap pin`, no node). The first graph and "Lay out again" lay
  out everything. Afterwards nothing that is placed moves: nodes that leave
  are removed, new nodes are placed next to their neighbours (an object
  beside its siblings in the app box) and an incremental fcose run holds
  every placed node with `fixedNodeConstraint`; fcose's small overall
  shift is undone so placed nodes keep their exact position. Toggling
  layers or topics-as-nodes uses the same path. Checked headless on the
  busy fixture: a new ROS 2 node and topic edge, a new object, an object
  gone, a whole board gone, topics as nodes on and off: 0 of 43-45 placed
  nodes moved (max 0 px).
- A missed diff (refetch of the whole graph) keeps the positions of the
  nodes that are still there.

## Rates: how they are measured, and what it costs

- **Only while a page asks.** `RateLease` rows (key `*` or a topic id, 30 s,
  renewed by the page every 10 s; `POST /rates`). `*` while "Measure all
  topics" is ticked; the topics of the selected topic or topic edge while
  its details are open. The bridge reads the live leases every 0.5 s.
- `*`: one subscription `<domain>/**` per ROS 2 domain seen in the tokens
  (rmw_zenoh's data keys are `<domain>/<name>/<type>/<hash>`; in the W1
  relay's ACL the console may read `0/**`). A single topic:
  `<domain>/<name>/**`, not taken when a wildcard covers it. When leases
  end the subscriptions close and the topics they measured are forgotten.
- `Bridge::Rates`: per topic, one-second buckets over a 5 s window (rate
  and bytes per second, the current second counted partly), the number of
  messages, and the time, size and first 4 KB of the last message. Several
  publishers on a topic add up. The preview is decoded (`Bridge::Cdr`:
  std_msgs numbers and strings, Vector3 / Point / Quaternion / Twist /
  Pose2D, rcl_interfaces/Log, the header of 17 stamped types; else V1's
  string reading, else hex) on the main thread, only when a new message
  came. The watch panel uses the same decoder (the type comes from the key).
- Broadcast once a second (`rates` on ConsoleChannel): only the topics whose
  row changed, and the status (what is measured, paused or not).
- **Bounds**: 300 topics (more are counted as dropped), WINDOW + 1 buckets
  and 4 KB per topic: about 1.5 MB at most. Measured on this PC (Ruby
  3.2): `record` 0.6 us per message; a full snapshot of 300 topics 3 ms and
  43 KB of JSON.
- **The real cost is the traffic**: every message of every measured topic
  reaches the bridge (and is copied into a Ruby string by the binding),
  across the relay if the bridge is on the cloud router. A camera at 15 Hz
  x 900 KB is 13.5 MB/s. So when the measured topics bring in more than
  `ASTERISM_RATES_MAX_BPS` (8,000,000 B/s by default) the bridge closes the
  wildcards for 60 s, single topics go on, and the page shows "all topics
  paused". Measuring one topic costs that topic's traffic only.

### What it found, and the fixes

1. **The sim's ROS 2 node was missing from the graph.** The bridge's
   liveliness watches used asterism-zenoh's default queue (16). A watch
   reports the tokens alive now in one burst when it is declared (an
   rclcpp node alone has some 25), so most of them were dropped (16 of 31
   taken in this network). The watches now have the binding's largest
   queue (`LIVELINESS_DEPTH` 1024), and a watch that still drops is
   declared again with its set cleared (`Runner#check_follows`, logged:
   `liveliness <pattern>: N changes dropped, following it again`).
2. **Admin-space gets have the same limit, and it cannot be raised**: a
   get keeps 16 replies (asterism-zenoh 0.4.0 has no `depth:` on `get` /
   `liveliness_get`), and a router answers a wildcard in one burst. 13
   tokens here, but a busy network (the fixture's 24 Asterism tokens) is
   past it. The bridge now reads them through the session's `Get` and logs
   `<key>: N replies dropped ...` once, so a graph that misses parts says
   why. Reported to the gems.
3. **A topic edge listed, and measured, the hidden topics** (the
   `/talker` -> `/listener` edge also carries `/parameter_events`): the
   details now list only the shown topics, the hidden ones in a hint, and
   the page asks the bridge to measure only the shown ones.
4. **Several publishers on one topic.** rmw_zenoh's data key does not
   name the publisher, so `/chatter`'s rate is of both talkers (about
   2 Hz), on each of the two edges. The details say so ("Rate and messages
   count all 2 publishers of the topic").
5. **A board that comes back was drawn apart, and outside the view.** Its
   node, app and objects arrive in one diff, before its session: no object
   had a placed sibling or neighbour, so each was put on its own at a
   random height right of the drawing, and fcose pulled the new box to
   225 x 245 px past the view's edge. Now nodes placed in the same pass
   count as placed for the next ones, the children of a box that is new
   as a whole go two to a row and keep that after fcose, and a node or box
   that is new as a whole is moved inside the view (20 px margin). The
   placed nodes are untouched, as before.

The live check also moved the console to asterism 0.4.0: `Bridge::Objects`
calls through `Asterism[path, timeout:]` (seconds) and the proxy's
`asterism_meta` instead of the internal `Asterism.meta` / `Asterism.call`,
`Asterism::TimeoutError` instead of `Asterism::Timeout`, the bridge's
heartbeat carries `connection_count` (the page says "no router connected"
when it is 0), and one rescue of `Asterism::Error` covers the bindings'
errors.
