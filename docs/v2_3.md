# V2.3: ROS 2 nodes folded by machine

Stage V2.3 of the console (plan: the V table, V2.3). Done 2026-10-11 and
checked against the MuJoCo rover over ROS 2 (S1's compose), a P4 board
running a ROS 2 app (one node), the Linux sim running asterism_demo, and
recordings made before V2.3.

The rover alone is ten ROS 2 nodes in one container. Drawn one by one, they
took most of the graph, ten `peer` lines met at the router and a dozen
`/clock` edges crossed the drawing, while the question usually asked of
the graph was "what talks to the rover". Now the nodes of one machine are
one box by default, and the box opens on demand.

## What a machine is

ROS 2 does not say which machine or process a node runs on: its liveliness
token names the node and its Zenoh session, nothing more. The one hint is
the address the session comes from, which the router's admin space gives
(V2.1 shows it in a node's details). So:

- The ROS 2 nodes whose sessions come from the **same IP address** are one
  machine, when there are **two or more** of them. A node alone at its
  address is drawn as before.
- Asterism nodes are not folded: they have their own nesting (apps,
  objects), and the console is one of them.
- IPv4-mapped addresses (`[::ffff:192.0.2.5]`) count as their IPv4
  address. A node with sessions from two addresses goes by its first.

What it cannot tell: machines behind one NAT look like one machine. With
Docker Desktop's port publishing, every device on the LAN that reaches
zenohd through the published port arrives from the Docker network's
gateway (e.g. `172.20.0.1`): two ROS 2 boards on WiFi would be folded
together. Containers on the Docker network have their own addresses and
fold correctly. (V2.4 leaves the nodes from a gateway unfolded: docs/v2_4.md.)

## Folded (the default)

| Element | Drawn as |
|---|---|
| a machine | a purple box, larger than a node, with a second purple outline around it; labelled `<name or IP> (N ROS 2 nodes)` |
| its badges | the services and the topics with no counterpart of all its nodes, added up |
| topic edges to and from it | one edge per direction and other end, carrying all the topics of its nodes (the labels and rates as before) |
| topics among its own nodes | **not drawn** while folded (no loop on the box): an arrow from the box to itself says nothing a reader can follow, and the rover has a dozen. The details list them ("Topics inside") |
| its line to the router | one, with the roles and the sessions of all its nodes |
| with "Topics as nodes" | edges between the box and the topics; a topic whose publishers and subscribers are all inside one folded machine is not drawn |
| with "Sessions as points" | the sessions carry the box |

## Open

The details of a machine have "Open" (and "Fold"); the details of a node
in an open machine say which machine it is in and have "Fold" too. Open,
the machine's nodes are drawn as before V2.3, **with no box around them**:
V2.1 tried a box for a process, and fcose let it swallow the drawing (see
docs/v2_1.md). The first time a machine is opened its nodes are placed in a
ring where the box was, then laid out with everything else held still;
after that they keep their places. Folding puts the box back where it was
(the first time: where its nodes were).

The browser remembers which machines are open (`localStorage`,
`asterism.console.openGroups`), by the machine's name when it has one (so
an open machine stays open when its address changes) or else by its IP.

## Names

A machine is shown by its IP until it is given a name.

- **Who names**: admins, from the machine's details ("Name this machine",
  Save / Remove). A name is shared by every user of the console (it is in
  the database, `MachineName`), like the call permissions and the relay
  registry, which only admins change; everyone else sees the names.
- **What a name is kept with**: the ROS 2 node names of the machine when
  it was named (`/controller_manager`, `/diff_drive_controller`, ...), not
  the IP. An address changes (a container made again, DHCP); the nodes a
  machine runs do not, usually.
- **Matching**: a machine takes a name when the node names they share are
  at least half of the larger of the two sets: `2 * |M & N| >= max(|M|, |N|)`
  for the machine's names M and the name's N. Half of the larger set means
  neither a machine that grew a lot (many new nodes) nor one that lost most
  of the named nodes keeps the name; then it shows its IP again. When
  several names could go to several machines, the closest pairs go first
  (Jaccard, `|M & N| / |M | N|`), then the newer name; a name goes to one
  machine only (two copies of the same robot: one gets the name, the other
  shows its IP), and a machine takes one name.
- **Renaming** takes the machine's node names again (as they are now).
  **Removing** goes back to the IP.

The bridge reads the names with the admin space (every 2 s), so a new name
shows in every open page within a few seconds, as a diff.

## Where it is built

In the bridge: `Bridge::Groups.apply` (lib/bridge/groups.rb), a pure
function on a graph in to_h form, after `Bridge::Connections` (it reads the
nodes' `connections`) and before `Bridge::Marks`. The three are chained by
`Bridge::Graph.derive`, which `Graph#to_h` ends with and which
`RecordingsController#graph` runs on recorded graphs with **today's**
names. It is idempotent: it removes what it added before and adds it again,
so recordings made before V2.3 fold the same way.

Added to the graph:

| Part | |
|---|---|
| `r_group` nodes | `r_group:<ip>`, layer `ros`. Data: `ip`, `members` (node ids), `member_names`, `name` / `name_id` / `named_members` when a name matches, `services` / `clients` / `unmatched` of its nodes (each with its `node`), `connections` (its sessions, once each), `internal_topics` |
| data `group` | on each member `r_node` |
| folded copies of edges | `topic_link`, `attach`, `publishes`, `subscribes`, `carries`, `peer_link` and (V2.6) `via_router` edges touching a member, with the member replaced by its machine; `folded: true`. An edge between two machines gets a copy for each way of folding them. Copies with the same ends are merged (topics; sessions and roles) |

The page only chooses what to show: a machine's box while it is folded,
its nodes while it is open, and an edge when both its ends are shown, which
picks the right copy by itself.

`MachineName` (`machine_names`: `name`, `members` as a JSON array,
`created_by`) and `MachineNamesController` (`GET/POST /machine_names`,
`PATCH/DELETE /machine_names/:id`, JSON; changes for admins only). The
console page carries `data-console-admin-value` to show the form.
