# S2: a simulated robot as Asterism objects

Part of Asterism stage S2 (family-mruby: MuJoCo run from CRuby through
Fiddle, its two-wheeled robot exposed as Asterism objects; the report is
fmruby-core/doc/ruby_asterism/report/s2.md, the simulator is the asterism
repository's `examples/mujoco/`). Checked 2026-10-10 against zenohd 1.10.1,
with the robot's process, a Family mruby sim and a board on the network.
**No change to the console was needed**: the robot is an ordinary Asterism
node and its state an ordinary MessagePack key.

## What the robot looks like here

- **Graph**: node `mujoco`, app `rover`, objects `drive`, `state`,
  `world`, nested as for any Asterism node. The drivers (a board, the sim,
  CRuby) show as nodes without objects: they only call.
- **Calls**: an admin allows the objects under "Call permissions" (rows
  `mujoco` / `rover` / `drive` / `*` and `mujoco` / `rover` / `state` /
  `*`; `world` is left out so the page cannot reset the world). Then the
  details of `drive` list `cmd` (2 arguments) and `stop`, and
  `cmd` with `[0.2, 0.6]` moves the robot for half a second (the robot
  stops 0.5 s after the last command; the page sends one). Arguments are a
  JSON array, so the optional `by:` keyword cannot be given; the robot
  shows the driver as `?`.
- **Plots**: the Asterism key `asterism/mujoco/rover/state` (10 Hz, a
  MessagePack Hash): the field list offers `pose.x`, `odom.yaw_deg`,
  `speed.wheels[0]`, `imu.accel[2]` and the rest.
- **Recordings**: the same key and the network structure; the timeline
  plots the fields over the whole drive.

## The live check (2026-10-10)

| Item | Result |
|---|---|
| Graph | `mujoco` > `rover` > `drive`, `state`, `world`; the board, the sim and CRuby as nodes |
| Call permissions | two rows added on the page (`drive` `*`, `state` `*`) |
| A call from the page | `drive.cmd([0.2, 0.6])` => `{"v":0.2,"w":0.6}` in 8.1 ms; the robot's log shows the driver `?` |
| Plots | `pose.x`, `pose.y`, `odom.x`, `odom.y`, `pose.yaw_deg`, `odom.yaw_deg` during a test drive (1 m, then 90 degrees): 179 messages seen, all plotted |
| Recording | the state key and the structure for 25 s: 255 messages (250 of the key, 10.0 Hz), 124 KB, lost 0; the timeline plots `pose.x`, `odom.x`, `pose.yaw`, `odom.yaw` through a reset, the drive and the turn |
